# AI Usage

AI tools were used to help organize ideas, explore testing approaches, and improve the clarity of parts of this assessment. 
The following are representative examples of how they were used.

## Prompts Used

- **Test design:** “Review this scenario and identify key risks, missing requirements, and high-priority test scenarios.”
- **API testing:** “Suggest Postman assertions and important negative scenarios for an API involving financial transactions.”
- **Automation design:** “Propose a maintainable automation architecture for a configurable admin console with dynamic form controls.”
- **Release judgement:** “Evaluate the release risks in this scenario and recommend a risk-based go/no-go approach.”

These prompts summarize the type of assistance requested rather than reproduce every interaction verbatim.

## What I Kept

I retained suggestions that fit the assessment scenarios, including risk-based test prioritization, API checks for transaction failures and duplicate requests, stable locator strategies for automation, and evidence-based release criteria.

## What I Changed or Did Not Use

I adapted general suggestions to the specific requirements and constraints of each task. I did not treat suggested tests as executed results, 
claim that the proposed automation framework had been implemented, or assume that unresolved release risks were acceptable without supporting evidence.

## Responsibility

I reviewed and adapted the final submission and remain responsible for explaining its technical decisions, limitations, and alternatives.
